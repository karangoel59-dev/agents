# Recursive DAG Agent API

This project is an asynchronous REST API built around the [WriteHERE Recursive DAG Agentic Framework](./writehere-planner/README.md). It leverages Large Language Models (LLMs) to automatically break down high-level prompts into structured, multi-step sub-tasks (like chapters or report sections) and sequentially executes them.

The API provides endpoints to trigger long-form **Story** or **Report** generation tasks in the background, and a polling endpoint to check their real-time execution status.

## Features

- **Asynchronous Execution**: Tasks are run in background threads, so the API is non-blocking.
- **Automated Planning**: The `LLMPlanner` automatically breaks down goals into chronological sub-tasks (e.g., 3-chapter stories or 5-7 section reports) and injects tone guidelines for consistency.
- **State Polling**: Track the live execution of the directed acyclic graph (DAG) node-by-node.
- **Pluggable Architecture**: Easily extend by adding new planners in `planners/` and executors in `executors/`.

## Architecture

- **`main.py`**: The Flask application providing the REST API endpoints. It manages background threads and queries task status.
- **`planner_config.json`**: The configuration mapping DAG actions to the corresponding LLM agents.
- **`planners/llm_planner.py`**: The planning agent. It uses an LLM to outline the task and generates a structured JSON array representing the sub-tasks.
- **`executors/llm_executor.py`**: The execution agent. It takes individual sub-tasks, pulls in upper-layer context from previous nodes, and generates the actual content, aggregating it into the final output.
- **`writehere-planner/`**: The core recursive Directed Acyclic Graph (DAG) engine. 

## Installation

1. **Set up a Virtual Environment (Optional but recommended):**
   ```bash
   python -m venv venv
   source venv/bin/activate
   ```

2. **Install the Core DAG Engine:**
   Install the local `writehere-planner` package in editable mode:
   ```bash
   pip install -e writehere-planner/
   ```

3. **Install Dependencies:**
   Ensure you have Flask installed:
   ```bash
   pip install Flask
   ```
   *(Note: Authentication or API key setup for the underlying `OpenAIApiProxy` used by the DAG engine may be required depending on your environment).*

## Running the Server

Start the Flask server:

```bash
python main.py
```
The server will run at `http://127.0.0.1:5000`.

## API Usage

### 1. Start a Story Task
Generates a multi-chapter narrative.

**Request:**
```bash
curl -X POST http://127.0.0.1:5000/run/story \
     -H "Content-Type: application/json" \
     -d '{"goal": "A sci-fi story about an astronaut discovering a derelict alien ship."}'
```
**Response:**
```json
{
  "status": "started",
  "task_id": "story_task_2026-06-04_15-30-00"
}
```

### 2. Start a Report Task
Generates a multi-section analytical report.

**Request:**
```bash
curl -X POST http://127.0.0.1:5000/run/report \
     -H "Content-Type: application/json" \
     -d '{"goal": "A detailed market analysis on the future of renewable energy in Europe."}'
```
**Response:**
```json
{
  "status": "started",
  "task_id": "report_task_2026-06-04_15-35-00"
}
```

### 3. Check Task Status
Poll the status of an ongoing task.

**Request:**
```bash
curl http://127.0.0.1:5000/status/story_task_2026-06-04_15-30-00
```
**Responses:**
*While Running:*
```json
{
  "current_node": {
    "goal": "Chapter 1: The Discovery",
    "nid": "0_1",
    "status": "RUNNING"
  },
  "status": "running",
  "task_id": "story_task_2026-06-04_15-30-00"
}
```

*When Finished:*
```json
{
  "output_file": "/home/user/path/to/output/story_task_2026-06-04_15-30-00/article.txt",
  "status": "finished",
  "task_id": "story_task_2026-06-04_15-30-00"
}
```

## Output Structure

When a task completes, its results are stored in the `output/<task_id>/` directory:
- **`article.txt`**: The final aggregated text generated by the executors.
- **`nodes.json` / `nodes.pkl`**: A serialized state of the DAG execution.
- **`memory.jsonl`**: The memory log of the entire execution process.
